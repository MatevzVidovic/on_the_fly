The cutoff date selects a property snapshot

You recognised the date → model-version → calculated-unit-value chain. The part to adjust is “units of all transactions up to that date.”

In this pripis preparation, the units are building parts and parcel parts. The cutoff date selects the property data valid then. This is different from collecting all transactions that happened before a deadline.

Think: “What did this property look like then?”

If a building part’s recorded area changed in May, a January valuation uses its January state. A June valuation uses its June state. It does not add the old area and new area together.

The preparation code uses this condition on historical property records:

datum_od <= selected_date
AND datum_do > selected_date

That means the selected date lies inside the record’s validity interval: start included, end excluded.

Primary source: priprava_pripisa.py, functions pripravi_dele_stavb and pripravi_dele_parcel. This condition belongs to the inspected ISAM preparation; we have not yet proven the equivalent EV historical selection rule.

The complete picture, one extra link

Cutoff-date record
  ├─ prepared building-part / parcel-part records for that date
  └─ selected model version for that date
         └─ calculated-value record
              └─ points to the prepared unit it valued

The prepared units live in pripis_enote_deli_stavb and pripis_enote_deli_parcel. A value in pripis_vmxpd_x_enote points to its unit through id_rel_prip_enota and to its model/date selection through id_rel_vm_pd.

Read-only metadata and bounded queries on test_njihov_access, 2026-10-14:

  • Cutoff-date rows include 2026-01-01, 2025-01-01 and 2026-06-18.
  • A real pripis_vm_x_pd join links 2026-01-01 to model STZ, version 44, among other model selections.
  • pripis_vmxpd_x_enote.vrednost_izr is currently integer in PostgreSQL. The ticket’s decimal fix is still needed there; live Lift metadata has not been checked.
  • EV final-value tables exist: ev_del_stavbe_enota and ev_parc_enota. Both have vrednost, posplosena_vrednost and err_msg.

Historical EV tables and intermediate-data tables also exist. Their presence does not yet prove which dated records and model versions should be compared. That is the next investigation.
