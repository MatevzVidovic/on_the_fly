Integration repair / design proposal

Seven clear roles.
Two explicit phases.

Keep your SQLite handler and diff creator. Combine the remote SQL builder, key/date puller, and payload batch puller into one OracleSource module. Add a coordinator and an FMP row mapper so database reads, repair decisions, and write rules each have one home.

These are logical modules: named function groups in repair.py are enough to start. Each has a small interface; separate classes or files can come later if they help.

The final sequence

Run the regular integration first, then keep integrations writing this table stopped until repair finishes. RepairFlow drives both phases.

01 · Prepare

  1. Definition → Store: validate configuration; create run with the captured cutoff.
  2. OracleSource → Store: stream source keys/dates at or below cutoff.
  3. LiftTarget → DiffPlanner: stream bounded LIFT pairs; compare against SQLite source membership.
  4. DiffPlanner → Store: save removals, older-row upserts, and warnings; mark matched source keys seen.
  5. Unseen source keys become upserts. Mark preparation finished.

02 · Apply the reviewed run

  1. Load the prepared run; persist first apply time once.
  2. Store → OracleSource: fetch pending upsert payloads in pages of 10,000.
  3. Recheck saved pairs; changed/missing source rows become terminal warnings.
  4. Mapper → LiftTarget → Store: map, commit upserts, then mark outcomes processed.
  5. Commit saved UUID deletions, then mark processed.
  6. Fill point sampling fields; refresh direct views; finish the run and print warnings.
Prepare → Review saved diffs in SQLite → Apply
Prepare pseudocode — inventory, compare, save 
prepare(integration_uuid):
    definition = IntegrationDefinition.load(integration_uuid)
    run = store.create_run(definition.uuid, cutoff=definition.watermark)
    source, target = readers_for(definition)

    # Readers validate keys/dates; NULLs must not vanish in cutoff filters.
    # Store rejects duplicate source keys; target reader rejects target duplicates.
    for page in source.inventory(run.cutoff, page_size=10_000):
        store.save_source_pairs(run, page)

    for page in target.inventory(run.cutoff, page_size=10_000):
        for lift_pair in page:
            source_pair = store.lookup_source(run, lift_pair.key)
            decision = DiffPlanner.classify(source_pair, lift_pair)
            store.save_decision_and_mark_seen(run, decision, source_pair)

    for page in store.unseen_source_pairs(run, page_size=10_000):
        for source_pair in page:
            store.save_decision(run, DiffPlanner.classify(source_pair, None))

    store.finish_preparation(run)
    print_review_summary(run)  # failures leave the run unprepared
Apply pseudocode — recheck, commit, record progress 
apply(repair_uuid):
    run = store.require_prepared_run(repair_uuid)
    definition = IntegrationDefinition.load(run.integration_uuid)
    max_date = store.get_or_set_first_apply_time(run)
    source, target = readers_for(definition)

    for batch in store.pending_additions(run, page_size=10_000):
        payloads = source.fetch_payloads(batch.keys)
        writes, skipped = recheck_prepared_pairs(batch, payloads)
        mapped = [FmpRowMapper.map(row, definition, max_date) for row in writes]
        outcomes = target.commit_batch(mapped)  # includes skip-newer checks
        store.finish_entries(run, outcomes + skipped)

    for batch in store.pending_removals(run, page_size=10_000):
        outcomes = target.commit_batch(delete_by_uuid(batch))
        store.finish_entries(run, outcomes)

    target.complete(definition)  # sampling fill + direct view refresh
    store.finish_application(run)
    print_warning_summary(run)

    # On an execution error: stop. Rerun apply to resume pending entries.
    # Committed-but-unmarked writes replay safely; skipped entries stay finished.
    # If completion fails, the run stays unfinished and completion runs again.

Rules that cross the interfaces

Same value contract. Preserve the configured key type and FMP’s timestamp wall-clock fields, including fractions. OracleSource and LiftTarget return comparable pairs; RepairStore encodes them without losing meaning.

Bounded membership. Both inventories use date ≤ cutoff. Missing bounded source membership permits removal even if a newer source row exists. Saved removals have no Oracle recheck.

Commit before progress. LiftTarget returns outcomes after PostgreSQL commits. RepairStore then saves outcomes and warning counts. Upserts and absent-row deletions tolerate replay.

Existing agreements. No separate audit writes, locks, watermark changes, or configuration tracking. Configuration stays fixed. A later normal integration clears map caches.

Proposal based on the agreed repair spec. The SQLite table shape and repair rules stay the same; this proposal clarifies where each responsibility lives.
