C · Ali parcela sploh ima ustrezen ZPS?

WITH target AS (
    SELECT p.id, p.seq_id_parc, p.id_rel_fo, p.parcela_id,
           p.upostevan, p.delez, p.delez_bzps,
           f.id_rel_pe AS calc_fo_pe_id,
           CASE WHEN pe.id IS NOT NULL
                THEN COALESCE(pe.valid_to, DATE '2100-01-01') END AS datum_za_zps
    FROM public.pev_parcele p
    LEFT JOIN public.pev_fo f ON f.id = p.id_rel_fo
    LEFT JOIN public.pev_posebne_enote pe ON pe.id = f.id_rel_pe
    WHERE p.id = 'ab3206c6-b1c2-442b-8da7-841ff4038ab5'::uuid
), latest AS (
    SELECT DISTINCT ON (stavba_parcela_id, datum_od, datum_do)
           stavba_parcela_id, datum_od, datum_do,
           parcela_id, stavba_id, povrsina_zps
    FROM public.kn_nep_stavbe_parcele_h
    ORDER BY stavba_parcela_id, datum_od, datum_do, datum_sys DESC
), links AS (
    SELECT p.id AS pev_parcela_uuid, kn.*,
           p.datum_za_zps <= kn.datum_do AS datum_ustreza,
           EXISTS (
               SELECT 1 FROM public.pev_stavbe st
               WHERE st.id_rel_fo = p.id_rel_fo
                 AND st.stavba_id = kn.stavba_id
                 AND EXISTS (
                     SELECT 1 FROM public.pev_deli_stavb d
                     WHERE d.id_rel_sta = st.id AND d.upostevan IS TRUE
                 )
           ) AS ima_upostevan_del_v_istem_fo
    FROM target p
    JOIN latest kn ON kn.parcela_id = p.parcela_id
)
SELECT stavba_parcela_id, stavba_id, povrsina_zps, datum_od, datum_do,
       datum_ustreza, ima_upostevan_del_v_istem_fo,
       datum_ustreza AND ima_upostevan_del_v_istem_fo AS sodeluje
FROM links
ORDER BY stavba_id, stavba_parcela_id, datum_od, datum_do;
Kaj iščeš: sodeluje = true pomeni: datum ustreza in v istem FO obstaja stavba z upoštevanim delom. povrsina_zps mora biti znana za numerični izračun. 0 vrstic pomeni, da za to KN parcelo ni povezave; NULL/false pomeni, da del pogojev ni izpolnjen. Preglej vse vrstice, ne le dveh pričakovanih stavb.

Če povezave ni ali je ZPS NULL: sam vnos deleža ne zadostuje. Povezava se bere iz kn_nep_stavbe_parcele_h, ne iz površine parcele 1607. Dopolnitev KN povezav naj izvede skrbnik prek ustaljenega testnega postopka; nato ponovno izvedi C in sproži relevantno shranjevanje. Ta vodič ne izmišljuje INSERT-a v zgodovinsko KN tabelo, ker obvezni stolpci in postopek niso podani.

Iz priložene funkcije: datum preverja valid_to ≤ datum_do; dodatnega pogoja na datum_od ni. Za isti (stavba_parcela_id, datum_od, datum_do) vzame zadnjo različico po datum_sys. Različnih veljavnih vrstic ne združuj ročno samo po stavba_id.

WITH target AS (
    SELECT p.id, p.seq_id_parc, p.id_rel_fo, p.parcela_id,
           p.upostevan, p.delez, p.delez_bzps,
           f.id_rel_pe AS calc_fo_pe_id,
           CASE WHEN pe.id IS NOT NULL
                THEN COALESCE(pe.valid_to, DATE '2100-01-01') END AS datum_za_zps
    FROM public.pev_parcele p
    LEFT JOIN public.pev_fo f ON f.id = p.id_rel_fo
    LEFT JOIN public.pev_posebne_enote pe ON pe.id = f.id_rel_pe
    WHERE p.id = 'ab3206c6-b1c2-442b-8da7-841ff4038ab5'::uuid
), latest AS (
    SELECT DISTINCT ON (stavba_parcela_id, datum_od, datum_do)
           stavba_parcela_id, datum_od, datum_do,
           parcela_id, stavba_id, povrsina_zps
    FROM public.kn_nep_stavbe_parcele_h
    ORDER BY stavba_parcela_id, datum_od, datum_do, datum_sys DESC
), links AS (
    SELECT p.id AS pev_parcela_uuid, kn.*,
           p.datum_za_zps <= kn.datum_do AS datum_ustreza,
           EXISTS (
               SELECT 1 FROM public.pev_stavbe st
               WHERE st.id_rel_fo = p.id_rel_fo
                 AND st.stavba_id = kn.stavba_id
                 AND EXISTS (
                     SELECT 1 FROM public.pev_deli_stavb d
                     WHERE d.id_rel_sta = st.id AND d.upostevan IS TRUE
                 )
           ) AS ima_upostevan_del_v_istem_fo
    FROM target p
    JOIN latest kn ON kn.parcela_id = p.parcela_id
), measured AS (
    SELECT p.*, (
        SELECT SUM(l.povrsina_zps) FROM links l
        WHERE l.pev_parcela_uuid = p.id
          AND l.datum_ustreza IS TRUE
          AND l.ima_upostevan_del_v_istem_fo IS TRUE
    ) AS vsota_zps
    FROM target p
), expected AS (
    SELECT m.*,
           CASE WHEN delez IS NULL THEN NULL::numeric
                ELSE GREATEST(delez - vsota_zps, 0) END AS numericni_rezultat
    FROM measured m
)
SELECT seq_id_parc, upostevan, delez, delez_bzps AS shranjeno,
       vsota_zps,
       CASE WHEN upostevan IS TRUE AND calc_fo_pe_id IS NOT NULL
                      AND vsota_zps IS NOT NULL
            THEN numericni_rezultat END AS pricakovano_ob_izracunu,
       CASE
         WHEN upostevan IS NOT TRUE
           THEN 'PRIMERJAJ PREJ: neupostevana parcela ohrani vrednost'
         WHEN calc_fo_pe_id IS NULL
           THEN CASE WHEN delez_bzps IS NULL THEN 'UJEMANJE: NULL brez FO-PEV'
                     ELSE 'NAPACNO: pricakovan NULL brez FO-PEV' END
         WHEN vsota_zps IS NULL
           THEN 'PRIMERJAJ PREJ: UPDATE ohrani; INSERT NULL'
         WHEN delez_bzps IS NOT DISTINCT FROM numericni_rezultat
           THEN 'UJEMANJE'
         ELSE 'NEUJEMANJE'
       END AS kontrola
FROM expected;
Kaj iščeš: Pri izpolnjenih pogojih: shranjeno = pricakovano_ob_izracunu in kontrola = UJEMANJE. vsota_zps je S za trenutno stanje. UJEMANJE potrjuje stanje, ne pa tega, da je workflow res tekel enkrat. PRIMERJAJ PREJ zahteva začetni posnetek.

5 · Preveri samo workflow in zabeleži zaključek

E · Ali so stari računski prožilci odstranjeni?

SELECT n.nspname AS shema, c.relname AS tabela, t.tgname,
       t.tgenabled, pg_get_triggerdef(t.oid) AS definicija
FROM pg_trigger t
JOIN pg_class c ON c.oid = t.tgrelid
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE NOT t.tgisinternal AND n.nspname = 'public'
  AND t.tgname IN ('tr_pev_parcele_delez_bzps',
                  'tr_pev_stavbe_delez_bzps',
                  'tr_pev_deli_stavb_delez_bzps');
Kaj iščeš: Po uvedbi workflowa pričakuj 0 vrstic, ne le onemogočenih prožilcev. Če so prisotni, numerično ujemanje še ne dokazuje workflowa. Njihove odstranitve ne izvajaj na svojo roko v tem vodiču.

V dnevniku workflowa za čas tvojega shranjevanja poišči dogodek, prizadeti FO in seq_id_parc 2789407. Preveri en logični preračun, odsotnost rekurzije po zapisu delez_bzps ter končni rezultat po hitrih spremembah. Imena orodja za dnevnik in njegovih polj niso podana; skrbnik naj pokaže dejansko lokacijo.

Obvestila ni pri ohranitvi zaradi manjkajočega ZPS, preskoku ali nastavitvi NULL. Če je izračun izveden, a vrne isto številko, uskladi pričakovano obvestilo s skrbnikom: to ni isto kot ohranitev zaradi manjkajočega ZPS.

Povrnitev prvotnega stanja: vrni povezave, upoštevanost in dele po posnetku PREJ. Tvoj začetni delez in delez_bzps sta NULL. Če brez ZPS samo počistiš delez, se lahko delez_bzps zaradi pravila ohranitve ne počisti. Zato povrnitve ne označi kot uspešne, dokler oba polja v SQL ne ustrezata začetnemu stanju; preostalo povrnitev naj opravi skrbnik po dogovorjenem postopku.

Dokaz za vsak test

Zabeleži čas, dejanje, stanje PREJ, S, pričakovano vrednost, dejansko vrednost v bazi, oba odprta prikaza, obvestilo in ID izvedbe workflowa. Pričakovan izračun in ohranitev sta različna izida.

Preverjanje vodiča: SQL primerjan s priloženo funkcijo in sintaktično preverjen s PostgreSQL parserjem. SQL ni bil izveden na test_nas_db. Zasloni so shematski; dostop do aplikacije ni bil na voljo. Datumsko polje 01.01.3000 iz drugega dela obrazca ni samodejno PE valid_to — tvoj SQL za PE kaže NULL.
