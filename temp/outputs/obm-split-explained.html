Razreži · območja · staging

The split saves. The reconnection never starts.

The backend needs to know which original območje to copy connections from.
That identity is currently carried by a hidden form field: split_group_id.

The break: form configuration removes the identity.
The form-flags migration disables UUID fields. The backend-built form therefore omits split_group_id before you even click Save.
1 · Browser — standard geometry editor
You click Razreži, then Save

The browser splits the geometry into two pieces.

↓ standard create request
Create the new območje

New geometry + form values
split_group_id: MISSING

↓ after create succeeds, standard update request
Update the original’s geometry

✓ Two območja now exist in the database.

2 · Backend — triggered by the create request
Insert new md_geo_obm row

Fires md_geo_obm.after_insert.

↓ MdGeoObmInsertEventListener
Missing identity? Return immediately.

No error is raised. No workflow is started.

✕ no call reaches Temporal
GeoObmSplitWorkflow · Temporal

Find original → read all its cona links → copy them to the new območje, across model versions.

Result: 2 območja, but the new one has 0 connections.
No območja-specific SFC or custom edit renderer is configured in staging. Geometry saving and backend reconnection are separate steps; only reconnection depends on the missing identity. The second view illustrates the required handoff, not an implemented fix.
